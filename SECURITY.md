# Security Policy

## Supported Versions

We actively support the **latest release** of AutoNect with security updates. Older versions may receive critical fixes on a case‑by‑case basis.

| Version | Supported |
|---------|-----------|
| Latest release | ✅ |
| Previous major release | ⚠️ (critical fixes only) |
| Older releases | ❌ |

---

## Reporting a Vulnerability

We take security seriously. If you discover a vulnerability in AutoNect, please **do not** open a public issue – instead, follow these steps:

1. **Email us directly** at **i.j.slatna@gmail.com** (or use the GitHub Security Advisory).
2. Include a clear description of the vulnerability, steps to reproduce, and the potential impact.
3. If possible, provide a proof‑of‑concept or suggested fix.

### What to expect

- You will receive an acknowledgment within **48 hours**.
- We will investigate the issue and provide a preliminary assessment within **5 business days**.
- If the vulnerability is accepted, we will work on a fix and coordinate a responsible disclosure timeline.
- If declined, we will explain why.

### Responsible Disclosure

We ask that you give us a reasonable time (at least **30 days**) to address the issue before disclosing it publicly.

---

## Security‑related Configuration

To help keep your AutoNect instance secure, consider:

- **Disabling Auto‑Approve** (`safety.auto_approve = false`) – always review commands before execution.
- **Keeping your browser profile private** – the profile contains your DeepSeek login session; treat it like a password.
- **Using a dedicated browser profile** – do not reuse your personal browser profile for automation.
